# Directrices de Desarrollo - Snake MVP Unity

## Entorno y Lenguaje
- **Versión de C#:** C# 8.0 estricto.
- **Prohibido:** No utilizar target-typed new (`new()`), deconstrucción de tuplas en bucles ni características de C# 9.0 o superior. Usar constructores con tipo explícito (ej. `new Dictionary<KeyCode, KeyDirection>()`).

## Arquitectura del Proyecto (Clean Architecture / MVP)
El proyecto desacopla estrictamente tres capas:
1. **Model (`Assets/Scripts/Model/`):**
   - C# puro (sin heredar de `MonoBehaviour` ni referencias directas a UnityEngine en su lógica).
   - Administrado por `GameModel` que implementa `IGameContext`.
   - Utiliza la estructura inmutable `Coordinate(int x, int z)`.
   - Polimorfismo puro: entidades (`Entity`, `WallEntity`, `SnakeBodyEntity`, `FruitEntity`) y direcciones (`IDirection`).

2. **Presenter (`Assets/Scripts/Presenter/`):**
   - Orquestador en C# puro (`SnakePresenter`).
   - Máquina de estados: `IGameState` con implementaciones concretas (`MenuState`, `PlayingState`, `PausedState`, `GameOverState`).
   - Uso de patrón Null Object (`NullState`) para evitar chequeos de nulidad.
   - Es el dueño de las interfaces de vista (`IGameView`, `IUIView`, `IInputKey`, `ITicks`).
   - Usa el struct DTO `PosicionTablero` para transferir datos a la vista sin exponer `Coordinate`.

3. **View (`Assets/Scripts/View/`):**
   - Componentes `MonoBehaviour` pasivos (`VistaJuego`, `VistaUserInterface`, `InputKey`, `Ticks`).
   - **Regla estricta:** La Vista JAMÁS conoce al Modelo. Solo conoce las interfaces y DTOs del Presentador.
   - `VistaJuego` admite prefabs con fallback a primitivas por código.

## Estilo de Código y Reglas de Negocio
- Reemplazar cadenas de `if/else` y `switch` por diccionarios, polimorfismo o State Pattern.
- Nomenclatura natural y directa (ej. `_direcAsignadas` en lugar de nombres artificiosos).
